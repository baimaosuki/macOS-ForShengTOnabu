# NABU 25F71: writable Preboot state for cryptexd

The device's NABU-ABORT observer captured `unexpected failure: mkdirat: [30: Read-only file system]` from cryptexd PID 171. The reason string was successfully copied without truncation. Four user return addresses match the original 25F71 cryptexd at a unique image slide of `0x310000`. The call before runtime return address `0x10031bc40` opens `/System/Volumes/Preboot` with O_RDONLY|O_NOFOLLOW|O_DIRECTORY, then calls the directory helper that executes `mkdirat(parent_fd, "com.apple.security.cryptexd", 0705)`. The failing path is `/System/Volumes/Preboot/com.apple.security.cryptexd`.

The owner layout maps `/private/var/ngpu/preboot` from writable Data over `/System/Volumes/Preboot` using `native_cryptex_os_bind`. That helper requests MNT_RDONLY, and the original bindfs implementation also unconditionally forces MNT_RDONLY and rejects CREATE; its vnode table has no mkdir or write forwarding. Removing one mount flag or pre-creating the daemon directory does not establish a writable state store.

The fix replaces only the outer macOS Preboot view with a checked firmlink to the existing owner Data directory. It uses the same cross-device firmlink mechanism already used for the Data paths and VM directory. The Preboot backing must be a directory on the already validated writable APFS Data mount and its selected device. After linking, lookup through the public Preboot path must resolve to that same target. A transient O_EXCL write probe through that public path creates, writes, reads back and removes its own unique file. Mapping or probe failure propagates to checked Data startup before launchd.

The inner SystemOS System/usr bind mounts remain read-only, and the App APFS volume retains its original verified read-only mount. No whole-root remount, bindfs write implementation, cryptexd binary patch, or service disable is introduced. Existing root and Data images do not need replacement; the kernel's boot preparation creates and maps the backing path.

Host tests exercise the actual checked helper's success, failure and cleanup decisions and the full source preparation. CI compilation and independent prelink verification are required before delivery. Device verification must confirm `owner Data: cryptex view stage 5, status 0` (which now follows the successful public-path write/readback/remove probe), absence of this specific mkdirat EROFS abort, and subsequent service startup. This repairs the identified Preboot write defect; it does not establish that every later boot dependency or desktop graphics requirement is satisfied.

Original-binary and device evidence is retained in `out/nabu-mount-loop/cryptexd/preboot-mkdirat-callchain.json` and `preboot-erofs-device-evidence.json`, and is included in the test package.
