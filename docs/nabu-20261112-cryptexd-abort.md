# Device cryptexd abort and correction to process tracing

The device photo for kernel package `nabu-25F71-lifs-fskit-boot-fix.zip` shows PID 188 executing xpcproxy with `com.apple.security.cryptexd`, then `/usr/libexec/cryptexd`. System-event output records namespace 18/code 2 and exception 10/code `0x6000000`. In the matching XNU source these mean OS_REASON_LIBSYSTEM_CODE_FAULT and EXC_CRASH with SIGABRT. The AMFI line denies a core dump; it does not itself establish a code-signing kill. Description text is empty in the image. The repeated shared-region unnest notices do not identify the reason for the abort. This image cannot establish whether fskitd's lifs failure is gone or whether the complete mount loop is gone.

The preceding NABU-PROC exit=0 is a diagnostic bug: exec uses a replacement proc object with the same process unique ID. Teardown of the retired shadow proc consumed the live image's tracking record. Patch 18 now ignores `proc_is_shadow(p)` before inspecting or clearing the table. The regression test makes a shadow exit with the same unique ID, then checks that the real failed exit still retains its record and reason.

Patch 19 adds an opt-in observer in `abort_with_payload_internal` after the original throttle check, before building the exit reason. With `nabu-boot-proc=1`, selected filesystem/desktop processes report namespace/code/flags/internal flags, bounded reason text and copy errors, user PC/LR/FP/SP, and at most six candidate frame-chain entries. It samples the first four events per target and then one current event per five seconds. User addresses are read with copyin/copyinstr only; stripped address candidates are for diagnostics and never written to execution state. The original abort result, signal, throttle and policy remain intact. Null reason strings are visible; the return addresses allow locating the original assertion even when the description is empty.

Static review of the original 25F71 cryptexd identifies several startup paths that share the same generic fault code. These include directory operations, Image4 chip initialization and mounted-image enumeration; the observed code alone does not select one. `_hdi_copy_mounted` enumerates IOMedia and treats an empty iterator as success, so lack of IOHDIXController is not sufficient grounds to add another kext. Original-binary evidence is retained under `out/nabu-mount-loop/cryptexd/`.

The next package retains the original lifs addition and all earlier execution/storage/watchdog fixes. Its additional changes fix trace attribution and capture the actual abort call site. It is not yet a fix for the unknown cryptexd assertion or proof of desktop boot.
