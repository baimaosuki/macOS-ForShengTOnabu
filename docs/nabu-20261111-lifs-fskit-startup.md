# NABU macOS 26.5: restore the FSKit kernel service

Target stays macOS 26.5 build 25F71. The delivered baseline is `fbff0581e61dd67e5f15fbe703ac3979ac8d0ddf`. The baseline prelinks 13 Apple components and omits `com.apple.filesystems.lifs`.

The original 25F71 FSKit shared-cache code calls `IOServiceMatching("com_apple_filesystems_lifs")`, obtains a matching service, then opens its user client. If matching finds no service, it logs `Didn't find matching client` and returns `0xe0000001`. That propagates through `setMainMachPort:forDomain:` to `-[FSKitDaemon start]`, then original fskitd invokes `err(1, "error starting up the daemon")`. This is an exact dependency in the target build, rather than an assumption imported from sheng 27.3. Native framework addresses and the extraction/verification evidence are recorded in the package's `verification/lifs-dependency-evidence.json`.

The correction is to prelink the original 25F71 `com.apple.filesystems.lifs` in addition to the existing roots. Its personality publishes `com_apple_filesystems_lifs`, with `AppleLIFSUserClient`, matching `IOResources` after `IOBSD`. Its dependencies are kernel KPI interfaces; it adds no hardware driver. `config/nabu-macos26-desktop-prelink.json` lists every existing root plus lifs because `prelink_kcg_bind.py --root` replaces the default root list. Preserve the prior watchdog gate, PAC/DIT/SB/ObjC compatibility, mount policy, root and Data images.

The completed package must have 14 original Apple components including lifs, zero unresolved sites, and pass the independent prelink verifier. The original lifecycle and stderr trace are enabled in this test bundle so device output can show whether fskitd initializes and which caller issues later mount operations. The known missing-service failure is fixed by including the component; the entire mount loop and desktop startup still require device validation. Merely increasing PIDs or logging APFS remount messages does not establish their cause.
